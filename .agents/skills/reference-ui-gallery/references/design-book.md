# 디자인 라이브러리

디자인 레퍼런스, UI 컴포넌트/라이브러리, 아이콘/에셋, 디자인 시스템, UX 규칙을 모은다. 분류하지 않은 자료는 수집함에 둔다. 저장은 가볍게 하고 분석은 실제로 사용할 때 필요한 만큼 수행한다.

## 저장과 보기

1. 설정 참조의 `doctor`로 현재 갤러리 checkout을 확인한다. 원본은 그 저장소의 `references/<slug>/reference.json`, 선택적인 이미지 미리보기는 로컬 전용 `.reference-previews/`에 둔다.
2. 링크나 이미지를 받으면 `collect`로 저장한다. 제목/분류/태그/한 줄 메모는 입력에서 알 수 있는 만큼만 채운다. 분류가 없으면 기본 수집함을 사용한다.
3. 명령이 기존 URL을 찾으면 그 기록을 재사용한다. 이미 저장한 메모와 분류를 덮어쓰지 않는다. 내용을 수정할 때는 먼저 기존 기록을 읽고 필요한 필드만 병합한다.
4. `view`로 로컬 라이브러리를 열고 반환한 URL을 사용자에게 전달한다. 목록의 검색/분류와 새 항목의 이미지/원본 링크를 확인한다. 로컬 서버는 Ctrl-C로 종료한다.

갤러리 루트에서 실행하는 대표 흐름이다. 갤러리 밖에서는 [설정 참조](SETUP.md)의 전역 진입점에 같은 하위 명령을 전달한다.

```sh
uv --no-config run --locked --script scripts/gallery.py collect <slug> --source <url> --title <title>
uv --no-config run --locked --script scripts/gallery.py view
```

필드와 옵션은 `collect --help`, [빈 저장 기록](../assets/bookmark-template.json)을 따른다. URL, 이미지, 제목과 짧은 메모 중 하나로 저장한다. 직접 적은 UX 규칙은 URL 없이 제목과 `--note`로 보관할 수 있다. 링크에 이미지가 없으면 사이트 이름으로 표시한다. 저장하려고 평가문, 반례, 토큰, 프로토타입, 실행 검증을 채우지 않는다.

## 분류

| 분류 인자 | 보관할 것 |
|---|---|
| `reference` | 사이트/앱 화면, 레이아웃, 사용자 흐름과 모션 사례 |
| `library` | UI 컴포넌트와 구현 도구, 재사용 라이브러리 |
| `asset` | 아이콘, 폰트, 일러스트 등 소재 |
| `design-system` | 색상/서체/간격/상태/토큰과 사용 지침 |
| `guideline` | 탐색, 폼, 피드백, 오류 복구, 접근성, UX 문구 원칙 |
| `inbox` | 아직 분류하지 않은 링크나 이미지 |

자료 종류는 분류로, 찾을 상황은 태그로 남긴다. 예를 들어 로그인 화면은 `reference`, `로그인`/`모바일`은 태그다. 비슷한 자료가 있다고 새 최상위 분류를 계속 만들지 않는다.

## 기존 자료와 깊이 읽기

기존 `note` 기록의 상세 설명과 출처는 보존한다. 새 자료는 가벼운 `bookmark` 형식을 기본으로 사용한다. 사용자가 비교/분석을 요청하면 원문을 읽고 확인한 사실과 적용 제안을 구분해 필요한 메모를 보강한다.

실제 화면의 디자인 규칙과 토큰을 추출하라는 요청에는 기존 `new` 패키지와 산출물 계약을 사용한다. 수집을 이유로 UI 재현이나 토큰 추출을 자동 시작하지 않는다. 준비된 자료를 다른 제품에 적용하는 구현은 그 제품의 워크플로가 맡는다.

## 로컬 보관과 공개

`collect`는 로컬 파일만 쓴다. Git commit/push, 스킬 설치, 공개 발행을 수행하지 않는다. `.reference-previews/`는 이미지 저장 시 갤러리 `.gitignore`에 추가하며 공개 빌드에서 읽지 않는다. 이 이미지는 로컬 파일 백업 대상이고 Git 원격에 보관되지 않는다.

`view`는 미공개 자료와 로컬 이미지를 포함한 미리보기를 loopback에서 연다. `build` 기본값과 GitHub Pages는 publication 검토를 통과한 기록만 내보낸다. 공개 Git 저장소에 commit/push하는 메타데이터도 공개 자료이므로, 미공개 메모나 개인 링크를 함께 올리지 않는다. 공개할 링크/요약과 자산을 검토한 뒤 기존 publish/finish 범위에 따른다.

도구를 갱신한 뒤 갤러리의 기능 worktree에서 `bundle --project-skill --apply`로 생성 묶음을 준비한다. 반환한 managed/removed 파일을 함께 반영하고 대소문자를 포함한 Git 경로를 확인한다. 직접 생성 사본을 편집하지 않는다.
