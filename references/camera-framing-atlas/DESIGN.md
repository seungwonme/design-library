# Camera Framing Atlas

## 범위와 디자인 원칙

이 항목은 웹 브라우저에서 카메라 프레이밍, 렌즈, 환경 관계를 비교하는 33개 개념 도식 갤러리입니다. 사용자는 검색/분류 필터로 항목을 좁히고, 각 카드의 Canvas 도식과 설명/제한/QA 관찰 기준을 함께 읽습니다.

원본 영상이나 영화 장면을 복제하지 않고, 휴머노이드·카메라·격자·가림막·입자·색면을 직접 그립니다. 하나의 화면에서 카메라와 피사체의 관계가 보이고, 광학 표현은 정확한 광학 시뮬레이션이 아니라 명시한 개념 근사로 제한합니다.

## 토큰과 의미

`tokens.json`이 색상, 글꼴, 경계, 모서리, 간격, 컨트롤 크기와 모션의 정본입니다. `base` 토큰은 따뜻한 중성 캔버스와 높은 대비의 카드 표면을 정의하고, `dark` 토큰은 같은 정보 위계를 어두운 녹색 계열로 전환합니다.

- `font-sans`: OS에서 사용 가능한 시스템 UI 글꼴 스택입니다.
- `bg`, `surface`, `text`, `muted`, `line`: 페이지/카드/본문/보조 문구/경계의 의미 색상입니다.
- `accent`, `accent-2`: 도식의 주 피사체와 환경 강조입니다.
- `focus`: 키보드 포커스 링입니다.
- `radius`, `gap`, `control`, `motion`: 카드 모서리, 그리드 간격, 조작 대상, 선택적 전환의 규칙입니다.

## 레이아웃과 밀도

넓은 화면에서는 카드가 2열로 배치되고, 각 카드는 16:9 Canvas 미리보기와 설명 영역을 가집니다. 최대 콘텐츠 폭은 CSS에서 제한하며, 검색/필터는 헤더 아래 한 줄에 둡니다. 900px 이하에서는 카드가 1열로 바뀌고 필터가 검색 아래로 내려갑니다. 560px 이하에서는 페이지 여백과 카드 본문을 줄여 긴 한국어 설명이 잘리지 않게 합니다.

카드 안의 정보는 제목, 영어 이름, ID, 설명, 제한, 관찰, 시작/끝 기준 순서입니다. 긴 텍스트는 줄바꿈되며, 빈 검색 결과는 동일한 위치에서 별도 상태로 표시됩니다.

## 컴포넌트와 상태

- 헤더: 갤러리 목적과 공개 범위를 설명하고 밝은/어두운 화면 토글을 제공합니다.
- 검색: 입력 즉시 33개 메타데이터/제목/영어 이름을 필터링합니다.
- 종류 필터: 전체, 구도, 광학/환경을 `aria-pressed`로 노출하며 현재 개수를 보여 줍니다.
- 카드: Canvas 도식, 정적 상태 표기, 설명 목록, 출처 링크, 다시 그리기 버튼으로 구성됩니다.
- 로딩/오류: 매핑 JSON을 읽기 전에는 카드가 비어 있고, 요청 실패 시 `role=status`로 사용할 수 있는 빈 상태 메시지를 표시합니다. 현재 갤러리는 정적 JSON을 읽으므로 별도 서버 저장 상태는 없습니다.
- 다크 모드: 토큰과 Canvas 팔레트를 함께 전환하며 다시 그리기 없이 카드 전체를 재생성합니다.

## 표면과 합성

카드와 입력 표면은 불투명에 가까운 `surface`를 사용해 Canvas 도식과 긴 설명의 대비를 우선합니다. 배경은 중성 단색에 제한된 radial highlight만 사용하며, 외부 이미지나 로그인 데이터는 참조하지 않습니다. 카드 그림자는 콘텐츠 그룹을 분리하는 정도로만 사용하고, Canvas 자체의 배경과 카드 표면을 분리합니다.

## 모션과 접근성

모든 33개 항목은 정적 개념 도식이므로 `motion:false`입니다. Canvas의 `sample(t)`는 동일한 정적 구성과 진행값을 반환하며 자동 재생을 사용하지 않습니다. `prefers-reduced-motion: reduce`에서는 CSS 전환을 끄고, 검색/필터/테마 상태는 키보드로 조작할 수 있습니다.

Skip link, 명시적 검색 라벨, 버튼 이름, `aria-pressed`, `aria-live`, Canvas `aria-label`, visible focus outline을 제공합니다. 도식의 의미는 카드 본문의 텍스트 QA 기준으로도 읽을 수 있습니다. 전체 WCAG/스크린리더 감사가 아니라 이 갤러리의 키보드/이름/대비 범위만 검증했습니다.

## 플랫폼과 구현

정적 GitHub Pages 웹으로 구현했습니다. Canvas 2D와 바닐라 JavaScript를 선택한 이유는 프레임워크나 백엔드 없이 33개 도식을 독립적으로 확인하고, 각 도식의 렌더 호출을 테스트하기 쉽기 때문입니다.

로컬 실행:

```sh
python3 -m http.server 4173
```

저장소의 `index.html`은 카드 갤러리 진입점이고, `preview-camera-framing.js`는 모든 도식을, `app.js`는 JSON 로딩/필터/테마를 담당합니다. `camera-map-framing.json`은 카드 메타데이터와 QA 기준의 정본입니다.

## 분석과 디자인 결정

이 항목의 원본은 특정 제품 UI가 아니라 독립적으로 작성한 카메라 개념 목록과 설명입니다. 따라서 REA로 외부 앱을 추출하지 않았고, Taste/prototype 비교도 실행하지 않았습니다. 대신 공개 전 실제 갤러리 URL을 브라우저로 확인하고, 기존 갤러리의 정적 HTML/CSS/JS 구조를 유지했습니다.

도식 결정은 다음과 같습니다.

- 안정적인 `framing:` namespace로 preview ID를 고정했습니다.
- 인물 수, 전경/후경, 카메라 높이, FOV, 가림과 환경을 시각적으로 분리했습니다.
- 어안, 틸트 시프트, 망원 압축, 전방위 재투영, 수중은 근사임을 카드 제한사항과 README에 공개했습니다.
- 정의되지 않은 숏 크기 경계는 선택 해석으로 기록하고 표준 정의라고 주장하지 않습니다.

## 재사용 검증과 차이

검색/필터/다크 모드가 같은 카드 구조를 유지하고, 33개 렌더러가 같은 `draw(canvas-or-context, previewId, t, options)` 계약을 공유합니다. 대표 화면은 전체 갤러리이며, 검색 결과 축소 상태와 광학/환경 필터를 새 화면 상태로 확인했습니다.

원본 장면과의 픽셀 동일성은 목표가 아닙니다. 실제 카메라 렌즈, 센서, 굴절, 배우 동선, 조명과 영화 미장센은 단순화했습니다. 브라우저에서 확인한 것은 공개 Pages의 렌더링과 상호작용이며, 모바일 실기기/Safari 네이티브 확인은 범위 밖입니다.
